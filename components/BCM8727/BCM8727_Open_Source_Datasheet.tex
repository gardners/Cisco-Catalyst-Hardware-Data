\section{Management and status}
\subsection{MDIO and PHY identification}
Clause 45 device addressing and MMD accesses are supported \m{P}. Terasic U6 shows MDC2/MDIO2, optional dual-device MDC1/MDIO1, and hardware PHY address straps \m{R}. Linux's \texttt{bcm87xx} driver identifies BCM8727 using PHY ID \texttt{0x0143bff0} read from PHYXS (MMD 4) identity fields \m{S}\src{L}. This ID is a driver-match constant, not a proof that all suffix revisions use it.

\subsection{Boot, NVM and optics-control pins}
The device exposes SPI ROM clocks, data and chip select per channel; serial boot enable at H10; a configurable BSC/two-wire interface, and per-channel optics control/status. The presence of these pins does not establish a mandatory external ROM image or boot algorithm. The public product brief does not provide an ordered register initialisation sequence, strap truth table, default PHY addresses, nor firmware image format. Each is \unk.

\section{Open-source register map (partial)}
\label{sec:register-map}
\textbf{Address convention:} All register references use IEEE 802.3 Clause 45 \textbf{(MMD, 16-bit register)} tuples, not flat addresses. MMD 1 is PMA/PMD, MMD 3 is PCS, MMD 4 is PHY XS, and MMD 7 is AN. An offset appearing in another MMD is a \emph{different register}. Numeric addresses prefixed \texttt{0x} are hexadecimal. \textbf{Tables below contain observed uses and known gaps, not a complete Broadcom register specification.}

\textbf{Interpretation:} These source changes are credible experimental register evidence. They do \emph{not} establish an ordinary self-contained 2.5G mode on arbitrary hosts, nor 2.5G support on a particular BCM8727 suffix, board or firmware revision. A full bring-up requires host-SerDes configuration, optics compatibility, board timing and status validation. No evidenced 5G mode or four independent 1G logical ports has been located for BCM8727.

\subsection{Register-access and SFP EEPROM observations}
The \texttt{bnx2x} PHY driver implements SFP EEPROM reads by programming the BCM8727's MMD 1 two-wire control window: offset \texttt{0x8000} (transfer/status), \texttt{0x8002} (byte count), \texttt{0x8003} (EEPROM address), \texttt{0x8005} (slave address), and \texttt{0x8007+i} (byte buffer; low eight bits). It checks status bits \texttt{0x000C}, with documented driver values idle \texttt{0x0000}, complete \texttt{0x0004}, in progress \texttt{0x0008}, failed \texttt{0x000C}. \m{S}\src{H}\src{N}

This is a \emph{PHY-internal controller accessed over MDIO}, not evidence that the host directly drives an I\textsuperscript{2}C pair on the Cisco connector. The serial EEPROM internal to the \emph{Cisco sled} is a separate component; its protocol and connector mapping are unresolved.

\textbf{Design warning:} A Linux registration of \texttt{PHY\_ID\_BCM8727} may use a masked ID match; a diagnostic program should read both Clause 45 ID words rather than assuming an exact 32-bit ID value on every revision.
